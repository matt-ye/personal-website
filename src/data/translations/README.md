# 手刻頁的英文翻譯素材

這裡放 one-more-step 與紀念頁的「中文原句 → 英文」對照表。

**這些檔案會直接影響網站輸出。** `StaticPageContent.astro` 在建置英文路由時讀取
本目錄（機制 C），把片段裡的中文換成英文；查不到譯文就讓建置失敗。
2026-08-17 遷移完成後，6 頁都有 `/en/` 網址。

## 為什麼先翻譯、後遷移

這批頁面彼此沒有共用模板，雙語機制各做各的（見 `StaticPageContent.astro` 的說明）。
先把翻譯做完，遷移時就只剩機械套用，兩件事不會互相卡住。

## 兩道守衛，缺一不可

`scripts/lib/extract-strings.mjs` 同時提供抽出與套用，**共用同一組語境判準**——
`check-translations.mjs` 保證「抽得到的每一條都有譯文」，只有在套用走同一套規則時，
這個保證才等於「英文頁不殘留中文」。

但那只涵蓋**抽取器看得見的東西**。所以套用後還有第二道 `findResidualCjk`：
換完再掃一次，排除註解、CSS、網址與 `KEEP` 之後還有中文就讓建置失敗。

> ⚠ 這道守衛不是多餘的。紀念頁曾有 12 條字串**既沒被抽出也沒被驗證點名**：
> 頁內一行 `.replace(/[&<>"]/g, …)` 的正則字面值裡有個 `"`，舊版的樸素斷詞
> 把它當成字串開頭，之後所有引號配對整批位移。抽取器看不見的東西，
> 對照表的驗證當然也看不見——只有驗「產物」的守衛抓得到。

## 檔案形狀

每頁一個 `.mjs`，匯出 `MAP`：

```js
export const MAP = {
  '中文原句': 'English',
};
```

用 `.mjs` 而不是 `.json`，是為了能寫註解——**片段的處理需要說明**（見下）。

## ⚠ 片段：不能逐條直譯

不少字串是被 `<strong>`／`<span>` 切斷的句子片段，例如：

```html
<p>重點是<strong>針對特定受眾</strong>提供具體可執行的知識</p>
```

抽出來會是三條獨立字串。**中英語序不同，逐條直譯拼回去會壞掉**，所以這些地方的
英文是「重新分配過」的——每一條負責的內容不一定和中文那條對齊，但**拼接後讀起來正確**。

改動任何一條片段時，要連同前後片段一起看。

## 大模板：MODALS_EN（investment-notes 專用形狀）

investment-notes 的 71 個 modal 是幾百字的 HTML 模板字面值，當 `MAP` 的 key
不可讀也難 diff，所以改成按 modal key 對照整段英文 HTML：

```js
export const MODALS_EN = {
  m1: { html: `...整段英文 HTML...` },
};
```

這正好是遷移時 `.en.json` 注入機制（見 aw32 的做法）要吃的形狀。
`check-translations.mjs` 會從來源頁解析出每個 modal 的模板與 key，
驗證：每個 key 都有英文、沒有多出來源頁沒有的 key、英文 html 裡沒有殘留中文
（KEEP 白名單除外）。

查無官方英文名的品牌（如 大戶投、口袋證券）依誠實條款保留中文原字，
並列入 `KEEP`。

## 語言鈕

這批頁原本只有中文，片段裡沒有任何切換 UI。英文版上線後由 `StaticPageLayout`
在 `SiteStrip` 補一顆——判準是「片段裡有沒有 `id="langBtn"`／`"langToggle"`」，
不維護清單。marketing 與 aw32 那批自帶語言鈕，不會多一顆。

鈕上的字刻意用**目標語言**（英文頁寫「中文」、中文頁寫「English」）：
要切過去的人看得懂的是那一邊的語言。
